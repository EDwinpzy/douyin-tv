# ADR 0001：原生 Compose/Media3 与 WebView 登录边界

- Status: Accepted
- Date: 2026-11-07

## Context

目标是在 Android TV 上完成最基本的抖音使用闭环：遥控器浏览推荐短视频、进入
直播广场、观看直播，并使用用户自己的账号会话。用户明确要求原生 Android，
不接受把完整网页作为应用界面的套壳方案。

抖音登录依赖官方网页的扫码流程，直接复刻认证协议会扩大账号与安全风险，也更容易
因风控变化失效。

## Decision

1. 推荐流、直播列表、焦点系统和所有应用界面使用 Kotlin + Jetpack Compose。
2. 短视频与直播使用 AndroidX Media3/ExoPlayer 原生播放。
3. 仅在扫码登录时使用 WebView 加载抖音官方网页；获得会话 Cookie 后立即关闭。
4. 会话 Cookie 使用 Android Keystore AES-GCM 加密保存在本机。
5. 不内置抖音 APK、不把视频播放嵌入 WebView、不代理或上传用户 Cookie。

## Consequences

正向：

- 遥控器焦点、播放暂停、返回栈和分辨率适配由应用完全控制。
- 视频画面保持原始比例，直播竖屏内容不会被强制拉伸。
- 登录沿用官方流程，不接触用户密码。
- 原生界面在低性能电视设备上比整页 WebView 更可控。

代价：

- 推荐、签名和媒体地址仍依赖网页接口，接口变化时客户端需要跟进。
- 登录页 DOM 变化可能影响二维码弹层探测。
- WebView 仍会引入 Chromium 运行时和登录页的网络依赖。
- 这不是官方 SDK 客户端，不能保证长期稳定或账号合规。

## Alternatives considered

- **完整 WebView 套壳**：实现快，但 D-pad 焦点、播放、比例和返回栈不可控，
  不满足“原生安卓、不要套壳”的要求。
- **复刻账号密码/扫码认证协议**：安全与合规风险更高，且更容易被风控变化破坏。
- **使用第三方非官方 SDK 播放**：维护性和可信度不足，仍无法解决接口稳定性问题。
